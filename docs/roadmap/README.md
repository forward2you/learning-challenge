# 产品阶段路线与验证总入口

规划日期：2026-09-15。状态：规划基线v1.1（离线包优先）；当前实现进展见下表与项目当前状态；规划不等同验收。

本路线整合用户至今全部需求，替代此前分析中的建议阶段编号。历史分析保持原样。阶段号表示本轮执行顺序，不对应用户最初的九个功能编号。

## 交付方式调整

依据分析008：主交付改为各平台离线应用包＋可导入题库/声库更新包，不要求域名、服务器或公网网页。浏览器本地运行用于开发和可选便携入口；PWA与公网发布改为后续可选。安装/分发可能涉及平台验证，不能承诺所有平台首次安装也完全断网或免费。

## 产品目标

面向小学一至六年级的知识挑战产品。语文、数学、英语按教材与学习进度组织；昆虫、日常常识独立建库。支持本地朗读、选择、口算、听写、手写、综合挑战，以及后期单人/双人约十分钟的掷骰子棋盘冒险。核心玩法离线可用，不要求用户录音或调用大语言模型。

## 可交付里程碑

- M1：阶段01技术验收完成，可作口算试玩原型。
- M2：阶段03完成，发布范围受限的三上三科试用版；不能宣称全小学覆盖。
- M3：阶段06完成，具备五类知识与同设备双人挑战。
- M4：阶段08完成，具备单人/双人棋盘冒险及已验收手写功能。
- V1：阶段09、10完成，达到[最终产品验收定义](final-product.md)。

阶段可交付内测包，公开发布另完成对应渠道验收。本规划不自动触发托管、商店提交、购买服务或联网功能开发。

## 规格驱动开发规则

每阶段先把本文档中的验收计划细化为 `specs/编号-功能/spec.md`、`plan.md`、`tasks.md`，明确测试输入和期望输出后再实现。路线文档不是“功能已实现”的证据。

每阶段提交：实现/内容包、自动化验证结果、人工复核记录、目标设备记录、用户试玩反馈、剩余问题。状态为“未开始/开发中/技术通过/用户试验待完成/已验收/阻塞”，不把缺少实机或孩子试玩写成通过。

下一阶段只依赖其必需的已验收能力。若兴趣试验提示明显挫败或流失，先修玩法，不以增加题量替代验证。涉及较慢的样本收集时，可以继续独立内容工作，但不得跳过发布验收。

## 共用验证准则

- 题库：本阶段发布集全部核对答案与解析；来源/版本/审核状态必填。发现错误修复并回归相关题目；未审核题不进入正式模式。
- 程序：关键状态转换、判分、题库筛选、保存恢复、失败降级自动化验证；只有外观微调不增加无意义测试。
- 设备：按[平台矩阵](platforms.md)记录实际设备、OS/浏览器版本、构建版本，模拟器不能替代全部实机验证。
- 离线：完整内容包就绪后断网冷启动、朗读、答题、结束保存、退出再打开；记录安装/下载所需网络与游戏运行所需网络的区别。
- 学习：比较同知识点的新题，识别“记住答案”和“理解知识”差异；提示使用单独记录。
- 儿童体验：记录能否独立开始、完成、理解反馈、是否自愿再玩、输后反应与家长提醒，不用使用时长代替兴趣。
- 小样本：阶段01/03等优先邀请5—8名三年级孩子；阶段09逐年级补样本。用于发现问题，不证明教育因果效果或市场规模。
- 试验门槛：除正确性和数据完整性要求外，人数和性能指标均为规划目标，可在试验前记录修订理由，不能看完结果再改门槛。

## 资源和排期

暂不承诺日历日期：教材逐条审核量、离线语音和手写选型、真实设备及儿童试玩安排、发布渠道资料都会影响进度。每阶段规格确定后，再估开发、内容核对和验收工作量；代码完成不能替代内容与设备验收。
