# 009 · 网页开发、离线应用打包

日期：2026-09-15。用户询问是否可以开发过程中采用网页版，交付时打成离线包。

## 结论

可以，采用同一套网页界面与核心逻辑开发，最终按操作系统封装为离线应用。与分析008的离线包优先方向一致：开发预览不要求购买域名或部署公网服务器。

## 开发与交付流程

1. 本机网页预览：通过localhost/127.0.0.1调试界面、题目、反馈及玩法。
2. 将题库与游戏规则作为共享核心，文件、持久存储、朗读、手写识别和生命周期操作通过平台适配接口调用。
3. 尽早制作最小安装包，验证同一界面在目标平台的语音、手写和存储能力；不等全部功能完成才首次尝试打包。
4. 发布时打包网页资源、题库、图片、声库及需要的识别资源，生成对应平台的应用包。
5. 在无开发环境的真实设备安装，断网冷启动并完成关键流程，确认没有依赖开发服务器或远程资源。

## 关键约束

- 不是把网页目录压缩成ZIP就等于跨平台应用；不同操作系统需要自己的封装、构建与安装验证。
- 开发预览服务只供开发使用，最终用户不必启动命令行服务器。
- 不依赖CDN、远程字体、云端语音或在线判分；资源需包含在应用包或已导入的本地内容包中。
- 网页与安装版可以共享界面和规则，但系统功能可能需要不同适配实现。浏览器本地语音/手写小样通过，仍需验证安装版。
- iOS/iPadOS等平台的安装与发行条件不会因使用网页技术而消失。
- 具体封装工具在阶段02根据语音、手写、存储与设备试验选定。本轮不锁定框架、不生成安装包。

## 对阶段规划的影响

阶段01继续本机网页开发；阶段02加入最小离线安装包试验；之后每个新增系统能力都进行网页和安装版验证；阶段10完成正式打包与发行验收。公网网站仍可选，域名和业务服务器不是开发或离线交付前置条件。
