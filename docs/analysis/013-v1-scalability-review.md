# 013 · V1题库、单元选择与扩展性复核

日期：2026-09-16。

## 当前事实

1. 三科题目不是大题库：语文、数学、英语各固定10题，每轮只随机顺序。数学口算是例外，它按运算范围生成较大的候选池，再随机抽10题。
2. 第一单元不可选：`grade: 3`、`semester: 1`、`unitId: unit-1`写在内容构造和筛选逻辑中，首页与答题页也直接写“第一单元”。
3. 当前结构适合验证，不适合长期扩展：`src/app.js`同时处理路由、状态、渲染、计时、存储、口算和选择题；全部三科题目放在一个文件；CSS高度压缩。继续加入多个年级、单元、题型、语音、手写与冒险会增加耦合和回归风险。

## 建议的重构边界

在扩展第二单元前先完成V1.1基础重构：

- `core/`：答题会话、自动推进、计分、抽题、事件和结果模型。
- `content/`：内容包schema、注册表、校验、版本迁移；按教材/年级/学期/单元拆包。
- `providers/`：固定审核题、规则生成题、未来图片/听写/手写题提供器，共用统一题目接口。
- `features/`：首页、范围选择、口算、选择题、结果与复习，各自控制器和视图。
- `platform/`：存储、文件、离线语音、手写和应用生命周期适配器。
- `styles/`：设计变量、基础组件和各功能样式拆分。

范围选择应由内容包元数据生成：先选年级/学期，再按学科列出可用单元；只显示已安装且已审核的内容。抽题接口接收 `{subject, grade, semester, unitIds, questionTypes, count}`，题量不足时明确提示。

数学需要两类题源并存：规则生成器提供大量可变计算题；教材审核题提供语文、英语、数学概念和应用题。生成题也要由知识点和难度约束，不能无边界随机。

## 推荐顺序

先重构且保持现有33项测试继续通过；再实现第一单元选择器（即使当前只有一个可选项）；然后增加第二单元内容包。这样验证的是可扩展结构，而不是继续在单文件中堆功能。

本轮只做架构复核与记录，没有修改运行代码。
